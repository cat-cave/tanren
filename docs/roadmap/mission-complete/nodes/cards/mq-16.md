# mq-16 — Merge-Queue-V2 backfill / one-way authority cutover

**Phase**: full (merge-queue)
**Node ID**: `mq-16`
**Deps**: mq-2, mq-5 · SP-8
**Node credit**: **0** until independent audit, full green gates, and merge

## Purpose and boundary

Finish the remaining one-way cutover to the durable V2 queue authority. Main already has the
sole `MergeAuthorityV2` contract in `engine/contracts/mergeAuthority.ts`, exact node/proof
materialization in `engine/merge/batchIntegrationNodeDrive.ts`, and durable group receipts in
`engine/merge/landGroupStore.ts`. The residual direct path in
`engine/merge/mergeAuthorityGate.ts` still synthesizes `integration_node:land-${runId}` and
derived digest values without a persisted `integration_nodes` / `integration_proofs` record.
mq-16 removes that automatic-land route and makes the existing exact-node path work for one or
more queued members. Despite the ledger label, **“backfill” is no SQL/data backfill**: the
clean-replace doctrine deletes the synthetic/direct route and rejects old direct configuration;
there is no dual-write, compatibility facade, replay, or historical authority import.

## Production call graph

`mergeForRun` → `MergeDispatcher` native-queue enqueue (the only automatic-land mode) →
`BatchMergeCoordinator.coordinate` → `PgBatchChecker` → existing `driveBatchThroughNode`
(jj-local materialization + `integration_nodes` / `integration_proofs`) →
**`CanonicalQueueAuthorityDrive.land`** (new, invoked for an authorized batch of cardinality
one or greater) → existing `landAuthorizedGroupPg` → `MergeAuthorityV2Impl.land` →
`PgLandGroupStore`. It replaces the current `<2` bypass in
`authorizeMultiMemberEmbark`, the two-member assertion in `landGroupStore.ts`, and the
synthetic `authorizeAndLand` call; it does not add a second authority implementation.

## Contract / Data model

There is no new Zod contract: consume the frozen `LandBindingEnvelope` / `AuthorizeLandInput`
in `mergeAuthority.ts` and the existing `memberKey` / six-component `proofReuseKey` in
`engine/contracts/integrationNodes.ts`. Delete `direct_merge` as an automatic merge mode from
the existing shared config contract and make an old value a validated configuration error;
`external_reviewer` remains non-automatic.

There is no migration and no backfill. The existing RLS-protected `integration_nodes`,
`integration_proofs`, `authority_decisions`, `land_groups`, and `land_group_members` remain the
only durable records. A one-member group must use those same rows and constraints, not a new
single-PR table or a nullable/synthetic node binding.

## Provable / callable / visible

- **Provable**: retain the frozen chain `integration.node.materialized` (or
  `integration.node.materialization_failed`), `integration.proof_root.composed`,
  `merge.group.formed`, and `merge.land_group.completed`; no legacy/direct authority event is
  emitted.
- **Callable**: the existing `GET /orgs/:orgId/projects/:projectId/merge-queue/authority-evaluations`
  now returns an exact one-member decision as well as a batch, still using its project/RLS guard.
- **Visible**: the existing `MultiMemberAuthorityPanel` renders cardinality-one canonical-node
  evidence; a missing node/proof is `unknown`/blocked, never an authorized direct merge.

## Fail-closed proof

Host CAS is reachable only after a persisted ready node, exact ordered members, matching
passed proof/root, and the V2 land-time revalidator; the `land-${runId}` subject and synthetic
envelope have no fallback. The gravest fail-open is landing a direct PR whose decision names an
unpersisted or mismatched integration node. Local verification exercises the real dispatcher →
coordinator wiring for a one-member queue and asserts V2 land; unit/real-PG tests prove direct
config, absent node/proof, changed base/member/root, and cross-org reads cannot land or appear
authorized. Independent adversarial GO injects the absent-proof negative control at the V2
boundary and confirms the host-land port is never called.

## Size / migration

Target 550–800 lines across dispatcher/config removal, canonical drive, single-member group
guard, evaluation projection, and tests; each source stays under 500. No migration; it touches
none of serialized `schema.ts`, `screens.ts`, `main.ts`, or `mountFeatureRoutes.ts`.

## Acceptance

1. A one-member automatic queue run materializes a real ready node, records a matching proof
   root, forms/completes one normal land group, and lands through `MergeAuthorityV2Impl`.
2. `direct_merge` / synthetic `land-${runId}` cannot be selected or reached; no dual-run or
   data-backfill path remains, while an external reviewer still cannot auto-land.
3. Missing/mismatched node, proof, member order, or base makes the V2 land call impossible;
   focused tests plus `just fast-check`, `just ci`, and `just smoke` pass before audit GO.
