# mq-14 — QueuePolicyV1 + full comparator operations

**Phase**: full (merge-queue)

**Node ID**: mq-14

**Deps**: mq-2, mq-4, mq-9 (unbuilt) · SP-4

**Node credit**: 0 until independent audit + green gates + merge.

## Purpose and boundary

Add a versioned declarative native-queue policy and one comparator control path for routes, priority/aging, partition capacity, freeze/pause/drain, named windows, and auditable commands. It builds on `MergeIntegration.native_queue` and `maxBatchSize` in `services/orchestrator/src/engine/config/shared.ts`, `reviewMerge/mergeDispatch.ts`, `contracts/mergeCoordinator.ts:selectNextMerge`, and persistent partition/lease model in `engine/merge/mergeQueuePartitionStore.ts`.

It consumes mq-9's unbuilt comparator contract at the card-defined interface; mq-9 is not reimplemented here. It leaves sole landing decision intact: `mergeAuthorityGate.ts` calls existing `MergeAuthorityV2.authorizeLand` then `land`; policy/control code never calls either MergeAuthority land method or a code-host merge method.

## Production call graph

Today non-drive native work reaches `MergeDispatcher.enqueueNative` through `mergeForRun` / `mergeDispatch`; the coordinator selects eligible entries with current `selectNextMerge`, then batch work reaches the authority gate. Native queue partitions already carry mode, capacity, state, generation, and pause reason in existing `merge_queue_partitions`.

The one new production entry point is `QueuePolicyController.apply(input)`. Admission wires `mergeForRun` -> `mergeDispatch` -> `MergeDispatcher.enqueueNative` -> native queue enqueuer / `PgMergeQueueModel.enqueue` -> `QueuePolicyController.apply(admission)` -> existing partition store. Coordination wires existing coordinator subscriber -> `BatchMergeCoordinator.coordinate` -> `QueuePolicyController.apply(coordinate)` -> existing `selectNextMerge`. HTTP commands use the same entry point.
The controller rechecks active policy/window/freeze through existing claim confirmation immediately before authority CAS; it cannot turn a held item into host land.

## Contract / Data model

Add strict frozen `QueuePolicyV1Schema` with `schemaVersion: "queue_policy.v1"`. It contains named target-branch routes; a typed matcher AST (branch, labels, paths, author, review, check, scope, schedule, `all`/`any`/`not`); priority/aging; serial/scoped/isolated partition mode; capacity/batch/deploy-group limits; and interruption policy. It has no shell, CI command, arbitrary expression, `/land`, or bypass field; `.tanren/ci.yml` remains the executable gate.

Add strict versioned `QueueCommandV1Schema` and `QueueWindowV1Schema`: commands are queue/requeue/dequeue/refresh/boost/clear-boost/pause/resume/freeze/unfreeze/drain with scope and idempotency key; windows are named allow/blackout intervals with timezone and scope. Neither schema contains merge-now or authority override.

At the next free migration slot at build time, add FORCE RLS `merge_queue_policies` (org/project/target branch/version/schema version/body/compiled hash/active/supersedes), `merge_queue_commands` (actor, command, idempotency key, payload/result, policy), and `merge_queue_windows` (policy, project/branch/scope/timezone/interval/kind), with composite FKs to existing `projects`, policy rows, and queue rows where referenced. Add immutable policy/route/priority snapshots to existing `merge_queue`; preserve its RLS and use composite org-scoped FKs. Revision never retroactively changes an admitted entry without an explicit re-evaluation record.

## Fail-closed proof

Invariant: an entry may proceed only under valid active policy, open window, unfrozen partition, and final claim-time recheck; every command is scoped, authorized, and idempotent. The gravest prohibited fail-open is a freeze or blackout arriving after proof completion but before code-host CAS, followed by land anyway.

Local verification rejects malformed/unknown policy fields, holds on missing policy or closed window, and proves duplicate commands have one durable effect/event. The independent adversarial GO freezes a batch after proof evaluation and before final claim: no MergeAuthority/CodeHost land call may occur. A malformed-policy negative control must hold rather than fall back to unconstrained FIFO; audit reconciles policy snapshot, command idempotency key, window decision, partition generation, and authority event chronology.
