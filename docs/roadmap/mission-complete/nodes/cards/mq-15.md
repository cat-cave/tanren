# mq-15 — Dashboard merge-train visualization + exportable signed artifacts

**Phase**: full (merge-queue)
**Node ID**: `mq-15`
**Deps**: mq-2, mq-3, mq-6, mq-7, mq-10, mq-13
**Node credit**: **0** until independent audit, full green gates, and merge

## Purpose and boundary

Make a completed merge train inspectable and exportable without inventing another authority
or proof chain. It extends the existing merge-queue screen at
`services/dashboard/src/routes/mergeQueue/index.tsx` / `components/mergeQueue/MergeQueueBody.tsx`,
the durable group/receipt writer `engine/merge/landGroupStore.ts`, and the post-merge order in
`engine/postMerge/subscriber.ts`. The artifact is a projection of the already-authoritative
node, decision, receipt, deploy, and demo evidence; it must not re-run CI, recreate an
authority decision, or treat a dashboard read as proof. `engine/contracts/cas.ts`'
`ProofSubstrate` remains the sole sealing/verification substrate--mq-15 adds no signer or
parallel CAS format.

## Production call graph

`PgLandGroupStore.recordLandReceipt` → existing `merge.land_group.completed` activity →
`PostMergeSubscriber.runChain` → existing deploy watcher → existing `DemoOnDeployWatcher` →
**`MergeTrainArtifactWatcher.check`** (new `RunMergeWatcher`, wired after `demoWatcher` in
`subscriber.ts`) → injected `ProofSubstrate.constructBundle` / `seal` / `verify` /
`persistBundle` → `PgMergeTrainArtifactStore`. The existing dashboard mount calls
`MergeQueueClient`; mq-15 adds its train/artifact client to that same screen, never a new
screen mount.

## Contract / Data model

`engine/contracts/mergeTrainArtifact.ts` freezes `MergeTrainArtifactV1` as
`version: 1`, `schemaVersion: "merge_train_artifact.v1"`, `.strict()`: org/project/group and
authority-decision ids, ordered node/member binding, proof root, receipt/main SHA, deploy
identity, demo result, `ProofBundleSealed` digests/key/signature, and canonical content hash.
Validation requires the exact member order and terminal evidence; it delegates signature
verification to the existing `ProofSubstrate`, not a UI-provided key.

`merge_train_artifacts` is an append-only projection: `(org_id,id)` key; `(org_id,project_id,
authority_decision_id)` → existing `authority_decisions`; `(org_id,land_group_id)` →
`land_groups`; `(org_id,bundle_digest)` → `cas_artifacts`; unique `(org_id,land_group_id)`.
It records node/proof-root, receipt audit id, deploy/demo evidence ids, sealed bundle digest,
and created time. The migration is the **next free slot at build time** (currently after
`0095`), enables and FORCEs RLS with the project/org policy; it never backfills an artifact.

## Provable / callable / visible

- **Provable**: append frozen `merge.train.artifact.sealed` through `PgEventStore`, with its
  schema/sensitivity/seed added beside the real merge vocabulary in
  `engine/events/schemas/wave4Vocabulary.ts`; it carries group/decision/bundle digest and key,
  not a second signature. It is emitted only after the bound existing
  `integration.proof_root.composed`, `merge.group.formed`, `merge.land_group.completed`,
  `deploy.verified`, and `demo.completed` chain.
- **Callable**: `GET /orgs/:orgId/projects/:projectId/merge-queue/train` and
  `GET /orgs/:orgId/projects/:projectId/merge-queue/land-groups/:groupId/artifact` return the
  strict manifest/bytes only through `runWithOrgScope` and `assertProjectAccess`.
- **Visible**: `MergeTrainPanel` in the existing merge-queue body shows ordered group members,
  integration node/proof root, receipt, deploy/demo terminal state, and a verified-artifact
  action; absent or unverifiable evidence is explicitly `unknown`, never green.

## Fail-closed proof

`MergeTrainArtifactWatcher` may seal only after one exact completed land group has a matching
authority decision/node/proof root, receipt, successful deploy, and successful proof-backed
demo; missing, duplicate, cross-project, or signature-invalid inputs persist no artifact and
the read/UI remain `unknown`. The gravest fail-open is signing a partial or mismatched train
as a successful delivery. Local proof is a real-PG/RLS route test plus watcher test that
tamper changes a member, demo outcome, or sealed bytes and proves export/verification fails.
Independent adversarial GO repeats the chain from the production subscriber and uses that
tampered terminal-demo negative control; it must find neither an artifact row nor a green UI.

## Size / migration

Target 800–950 lines across watcher/store/contract/routes/client/panel/tests; every source file
stays under 500. One migration, allocated only at build time, plus the serialized db
`schema.ts` export and `routes/experiments/mount.ts` route wiring; it does **not** touch
`screens.ts`, `main.ts`, or `mountFeatureRoutes.ts` because the merge-queue screen and route
mount already exist.

## Acceptance

1. A completed group with exact node, root, receipt, deploy, and demo yields one idempotent
   `MergeTrainArtifactV1`; its persisted `ProofBundleSealed` verifies off-line and its CAS
   bytes match the manifest.
2. Missing/failed demo, changed member/root, stale receipt, forged signature, duplicate watcher
   delivery, and cross-org GET each fail closed; no artifact is issued and the panel is not green.
3. Focused watcher/store/route/dashboard tests, then `just fast-check`, `just ci`, and
   `just smoke`, are green before the independent audit/negative-control GO.
