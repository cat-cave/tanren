**Bucket:** runtime verification / merge authority

**State:** implementing

**Base:** `origin/main` at `af537d2e`

## Outcome

Make the signed SP-3 `GateProofBundleV2` projection the one decisive native-gate
proof for an integration node. The batch checker must build a required-section
plan from the exact ordered members, seal the native CI and every actually-required
runtime-behavior/design-render section to the integrated head, persist that bundle,
and carry its root into the sole land envelope. Merge authorization and its
immediate pre-CAS revalidator must both reject an absent, unsealed, malformed,
head/member-mismatched, or section-incomplete V2 bundle.

`integration_proofs` is not an authority coordinate after this node. In
particular, no legacy reuse key or JSON proof may make a V2-bundle absence landable.

## Authority protocol

1. Materialize the ready integration node before invoking the native gate.
2. Resolve a required-section plan from the current node members. Native CI is
   always required. Runtime behavior is required only for member runs that actually
   require a pre-merge behavior verification; design render is required only where
   a member's project design contract requires it. Missing, malformed, duplicate,
   blank, or incomplete member evidence is unknown, never omitted.
3. Run the real `pre_merge` SSH gate and record its actual tier/step outcomes.
   An empty native execution has no positive evidence and is unknown.
4. Ingest validated section units through `ProofSubstrate`, construct and verify a
   single SP-3 bundle bound to `{node, ordered member set, integrated head, tree,
artifact, expected main}`, then persist its thin V2 projection under org scope.
5. Pass only a V2 root/bundle identity in the batch authority binding. The envelope
   root is exactly that persisted V2 root.
6. Both authorization and pre-CAS land revalidation reload the exact current bundle,
   verify the SP-3 seal and exact bindings, require positive/exact section coverage,
   and otherwise return a non-authorized/rederive state before host CAS.

## Negative controls

- Delete the V2 projection after an otherwise passing gate: evaluator blocks and
  land-time revalidation returns `revalidation_failed`; `landAuthorizedIntegration`
  is never called.
- Replace its root, bundle id, head, tree, member order, or member set: exact
  verification fails before authorization and before CAS.
- Delete a required section, duplicate it, replace its subject with a non-required
  member, or leave native CI without an executed step: the bundle is incomplete and
  blocks.
- Supply malformed/blank evidence fields or an RLS-hidden row: the decoder/reader
  returns unknown (or throws to the caller), never passed.
- Leave a valid legacy `integration_proofs` row while deleting V2: no authority path
  reads it, so land remains blocked.
