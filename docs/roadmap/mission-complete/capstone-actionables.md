# Capstone actionables — current inventory and execution breakdown

Audit baseline: `origin/main` / `728e2fd8c2a7e83c6ac5acdd0240e523fd6a2ae3` (2026-07-21).
This is a plan only. It deliberately changes no implementation artifact. All references are current `file:line` locations.

## Serial barriers

1. **MIG-BASELINE first and alone.** Make `db/migrations/0001_baseline.sql`, `meta/0001_snapshot.json`, and a one-entry journal from the present 103-file tip. Before any intended schema alteration, prove an empty database built from the old chain and one built from `0001` have byte-identical normalized `pg_dump --schema-only` output. Run schema drift and every RLS smoke. This freezes current schema truth; it does not change it.
2. **One migration owner after the squash.** `cap-schema-versions` has real columns (`design_system_releases.manifest_schema_version`, `symptom_contracts.schema_version`, `merge_queue_policies.schema_version`) and the fallback DB arm removes defaults. They must not independently append migrations. After the schema-format code PRs prepare their callers, one serialized `SV-DB-CONTRACT` PR creates `0002_capstone_schema_formats.sql` for those three column drops. After V2 deletion, the last fallback DB PR creates `0003_capstone_fail_loud_defaults.sql` for default drops. Each owns its snapshot/journal update. This deliberately leaves `0001` as the proven historical baseline and makes intentional behavior changes explicit; do **not** weaken the baseline zero-diff proof by folding them into it. A later re-squash would be a new, separately authorized migration barrier. The four SV code clusters may be developed in parallel worktrees, but they must retain a temporary DB write mapping until the serialized integration PR removes it; none can merge a final contract-field deletion by itself.
3. **Produce V2 before delete.** The design writer/derive path must persist a valid V2 contract and a real composer/render flow must consume it before `DesignContractV1`, the V1-downcast reader, and `migrateDesignContractV1ToV2` are deleted. Do not reorder this.
4. **Fallback deletions are last.** Every removed default/coalesce/compat arm lands with its omission test, after schema-format collapse and native-V2 deletion. The DB-default PR owns `0003`; tenant and code-only fallback PRs can run alongside it, but not before the prior capstone nodes.
